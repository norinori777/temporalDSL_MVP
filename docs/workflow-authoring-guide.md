# ワークフロー作成・実行ガイド

このガイドでは、Flowcraftの編集画面でワークフローを作成し、テスト実行する手順を説明する。Temporal DSLの内部構造は[実装設計書](architecture.md)、機能範囲は[MVP設計](mvp-design.md)を参照。

## 1. 起動

Temporal Serverとアプリケーションを別々のターミナルで起動する。

```powershell
temporal server start-dev
```

```powershell
yarn install
yarn dev
```

ブラウザーで`http://localhost:5173`を開く。画面上部に「API 接続中」と表示されていることを確認する。編集・保存にはAPIが必要で、テスト実行にはTemporal ServerとWorkerも必要。

## 2. 編集画面の基本

- 画面左の「ノードライブラリ」から、待機・入力・条件分岐・承認・画面表示・Webhookを追加する。
- 追加したノードは現在選択している工程の後ろに入る。後続工程があれば、新しいノードの後ろへつなぎ直す。
- 条件分岐を選択した状態でノードを追加すると、空いているOK、次にNGの接続先として追加される。
- ブロックを選択すると、右の「ノード設定」でノード名や固有の値を変更できる。
- 開始ブロックは削除できない。
- 条件ごとに分かれた経路は合流できない。経路の続きを作る場合は、続けたい枝の最後のブロックを選択してからノードを追加する。

開始ブロックと既定の待機ブロックが表示される。たとえば、待機後に入力を受けるには、待機ブロックを選択して「入力」を追加する。既存の待機はその後ろに残る。

## 3. 条件分岐を作る

1. 条件を判定する値を受け取るため、条件分岐の前に「入力」ノードを追加する。
2. 入力ノードを選択し、「条件分岐」を追加する。
3. 条件ノードの設定で比較する入力、演算子、比較値を指定する。
4. 「条件がOKの場合」の接続先を選ぶ。
5. 「条件がNGの場合」は別ノード、または「前の工程へ戻る」から戻り先を選ぶ。
6. 条件が通常分岐を使う場合は、OKとNGの両方に接続先を指定する。NGを戻りにする場合、NGの通常接続先は指定しない。

入力Aは文字列で、「等しい」「等しくない」「含む」を選べる。入力Bは数字文字列で、等値と大小比較を選べる。入力Bの先頭ゼロは入力値として保持されるが、数値比較では数値として扱われる。

分岐先には、まだ他の通常工程から接続されていないノードを選ぶ。同じノードをOKとNGの両方へ直接つなぐことはできない。各枝は別々のノード列として構成する。

### NGから前工程へ戻す例

入力Bが5より大きくない場合に入力へ戻すなら、入力ノードを条件の前に置き、条件の比較値を`5`、演算子を「より大きい」にする。OK先を後続工程に設定し、NG先は「入力へ戻る」を選ぶ。入力へ戻るたびに前回の入力値はクリアされ、再入力後に条件から先が再実行される。

## 4. 承認から戻す

1. 承認ノードより前に、修正に必要な入力などの工程を配置する。
2. 承認ノードを選択する。
3. 「『いいえ』の場合」で戻り先を選ぶ。
4. 「はい」は通常の次工程へ進む。「いいえ」は選んだ前工程へ戻る。

「拒否して終了」のままなら、いいえの操作でWorkflowは拒否終了する。戻り先は同じ実行経路の前工程から選ぶ。開始ブロックや未来の工程は選べない。

戻り先を選ぶと、その工程だけでなく、その後の工程も再実行される。Webhookへ戻る場合はHTTP送信も繰り返されるため、送信先の重複処理に注意する。終了条件が変化しない戻りループは終了しないので、入力値や承認結果によってループを抜けられる構成にする。

## 5. 各ノードの設定

| ノード | 設定・動作 |
| --- | --- |
| 入力 | 入力Aは空でない文字列、入力Bは数字のみ。後続工程と画面に引き継ぐ |
| 条件分岐 | 入力Aまたは入力Bを比較し、OK/NGの経路を選択 |
| 待機 | 1秒〜24時間の間で待機時間を設定 |
| Webhook | GETまたはPOSTと送信先URLを設定。入力済みのA/B値をクエリまたは本文へ含める |
| 承認 | 実行画面で「はい」または「いいえ」を選択。いいえは拒否終了または戻り |
| 画面表示 | URLを実行画面内のiframeに表示。「次へ」で続行 |

Webhookの送信先は保存時にURLが必要。POSTには`workflowId`と入力値がJSONで含まれる。GETには入力値がクエリパラメーターとして付く。

画面表示では入力値を実行画面にも表示し、iframeへ`workflow-input-values`メッセージで渡す。任意の外部ページ内に値を描画するには、そのページ側でメッセージ受信処理が必要。外部ページがiframe埋め込みを禁止している場合は、実行画面の「別タブで開く」を使う。

## 6. 保存とテスト実行

1. 画面上部でワークフロー名と各ノードの設定を確認する。
2. 「保存」を押す。DSLの検証に失敗した場合は通知メッセージに表示される。
3. 「テスト実行」を押す。現在の定義を保存してTemporal Workflowを開始し、実行画面へ移動する。
4. 入力・承認・画面確認が必要な工程では、画面の案内に従って操作する。待機は時間経過後に自動で次へ進む。

| 実行画面の表示 | 次の操作 |
| --- | --- |
| 値を入力してください | 入力Aと数字のみの入力Bを入力して続行 |
| 承認を確認してください | 「はい」または「いいえ」を選択 |
| 指定画面 | 内容を確認して「次へ」 |
| 待機中 | 設定時間の経過を待つ |
| 完了しました | Workflowの実行終了 |
| 拒否されました | 承認の「いいえ」に戻り先がない場合の終了 |

ワークフロー定義の保存先はAPIのメモリであり、API再起動で消える。Temporal Serverは実行履歴と進行中Workflowを管理するが、編集用定義ストアの代わりにはならない。

## 7. よくある問題

| 状況 | 確認すること |
| --- | --- |
| APIオフライン | APIが起動しているか、`http://localhost:4000/api/health`が応答するか確認 |
| 保存できない | 条件の比較値、OK/NGの接続、Webhook URL、待機秒数などを確認 |
| テスト実行を開始できない | Temporal Serverが起動しているか、Workerが`workflow-studio` Task Queueへ接続しているか確認 |
| 入力値が条件NGになる | 比較する入力・演算子・比較値を確認。入力Bは数値比較、入力Aの「含む」は大文字小文字を区別 |
| 戻りループが終わらない | 戻った後に再入力・再承認などで条件が変わり、ループを抜ける構成か確認 |
| iframeが空白 | 外部サイトのCSPや`X-Frame-Options`を確認し、必要なら別タブで開く |
| APIオフラインが続く（ポート5174で開いている） | 既定CORS許可Originは`http://localhost:5173`。重複したViteを止めるか、`CLIENT_ORIGIN`を実際の画面Originに合わせる |
